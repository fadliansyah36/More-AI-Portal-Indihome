## Phase 05 — Supabase schema reconciliation

Read-only inspection of canonical project confirms:
- 52 public base tables; RLS enabled on all 52.
- 48 RLS policies.
- 27 migration records.
- All observed `SECURITY DEFINER` functions are executable by `service_role`; no `anon` or `authenticated` execution grant was observed.
- Existing durable tables: `agent_runs`, `agent_run_steps`, `agent_run_events`, `agent_run_checkpoints`, `tool_executions`, `outbox_events`, `idempotency_keys`, `artifacts`.
- Existing worker RPCs: claim, heartbeat, checkpoint, finish, cancel and resume.
- Existing LLM request lifecycle RPCs and credit reserve/settle/release RPCs.
- All mappings recorded in `docs/implementation/supabase-schema-reconciliation.json`.

Security/performance findings:
- Four RLS-enabled tables have no policies: `network_gateway_nonces`, `network_verification_method_catalog`, `partner_access_code_redemptions`, `partner_access_codes`. This defaults to deny for client roles; confirm intended server-only access and consider explicit deny policies in a future reviewed migration.
- Leaked password protection is disabled (Auth dashboard setting; not changed).
- 52 unindexed foreign-key findings and 29 unused-index informational findings. No indexes were added/dropped without workload and query-plan evidence.
- All tables had `relforcerowsecurity=false`; service-role/server access must remain tightly constrained.

**Database decision:** no missing schema was established that justified a migration in this reconciliation pass. No production DDL, seed, RLS change, reset or destructive operation was performed.

## Phase 07 — Worker durable lifecycle adapter

Implemented in `apps/worker`:
- HTTPS-only Supabase worker RPC client.
- Service-role key accepted only through worker runtime settings.
- Claim, heartbeat, checkpoint and finish RPC payloads align to inspected SQL function signatures.
- Runtime requires a registered `AgentDispatcher` before it can claim work.
- Failures are returned as non-sensitive error codes; retry scheduling is delegated to the canonical SQL function.

The runtime is not deployed or started. No real user run has been claimed by this implementation. Dispatcher, cancellation propagation through all tools, outbox processing, recovery and end-to-end run tests remain open.
